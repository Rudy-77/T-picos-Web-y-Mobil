**1. Metodologías:** ¿Cuál es la diferencia principal entre una metodología de desarrollo tradicional (como Cascada) y una metodología ágil (como Scrum) frente a los cambios en los requisitos?

**R:** En Cascada los requisitos se fijan al inicio y es difícil cambiarlos después, en Scrum (ágil) los cambios se aceptan durante todo el proyecto trabajando en ciclos cortos (sprints) que permiten ajustar el producto según retroalimentación.

**2. Requerimientos:** Explica la diferencia entre requerimientos funcionales y no funcionales, dando un ejemplo de cada uno aplicable a una plataforma web.

**R:** Los funcionales describen qué debe hacer el sistema por ejemplo "el usuario puede iniciar sesión", en los no funcionales describen cómo debe comportarse por ejemplo "la página debe cargar en menos de 2 segundos".

**3. Arquitectura:** Describe el modelo Cliente-Servidor y explica brevemente cómo se comunican el frontend y el backend en una aplicación web moderna.

**R:** En el modelo Cliente-Servidor, el cliente (frontend) solicita datos o servicios y el servidor (backend) los procesa y responde. Se comunican típicamente mediante peticiones HTTP, muchas veces usando APIs REST que envían y reciben datos en formato JSON.

**5. APIs:** ¿Qué es una API REST y qué papel fundamental juega en la integración entre una aplicación móvil y los servidores (backend)?

**R:** Una API REST es una interfaz que permite que distintas aplicaciones se comuniquen mediante peticiones HTTP, es clave porque permite que una app móvil envíe y reciba datos del backend sin importar el lenguaje o plataforma de cada uno.

**6. Control de Versiones:** Explica la importancia de utilizar Git en un equipo de desarrollo de software y describe brevemente qué es un "merge conflict" (conflicto de fusión).

**R:** Git permite que varios desarrolladores trabajen en el mismo proyecto sin sobrescribir el trabajo de otros, además de llevar un historial de cambios. Un "merge conflict" ocurre cuando dos personas modifican la misma línea de código y Git no puede combinar los cambios automáticamente.

**7. Pruebas:** ¿Qué son las pruebas unitarias (unit testing) y por qué son cruciales para asegurar la calidad del software antes de su paso a producción?

**R:** Las pruebas unitarias verifican que partes pequeñas del código (funciones o métodos) funcionen correctamente de forma aislada, son cruciales porque detectan errores temprano, antes de que lleguen a producción.

**9. Patrones de Diseño:** ¿Qué es el patrón de arquitectura Modelo-Vista-Controlador (MVC) y cómo ayuda a organizar el código en el desarrollo de software?

**R:** MVC separa una aplicación en tres partes: Modelo (datos), Vista (interfaz) y Controlador (lógica que conecta ambos), esto organiza el código y facilita su mantenimiento.

**10. Seguridad:** Explica la diferencia técnica entre "autenticación" y "autorización" en el contexto de seguridad de una aplicación.

**R:** La autenticación verifica quién eres por ejemplo usuario y contraseña. La autorización determina qué puedes hacer una vez autenticado por ejemplo los permisos de acceso.
